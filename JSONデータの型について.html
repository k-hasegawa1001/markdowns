JSONの型について教えて

基本的にJSONからデータを取り出すときはstring型として扱われる？

Python、Go、JSの三つでそれぞれの扱いについて教えて

AI:

結論から申し上げますと、「JSONからデータを取り出すときにすべて文字列（string型）として扱われる」というのは誤解です。

通信やファイル保存の段階では、JSON全体が1つの長い「文字列」として扱われますが、プログラム内でデータをパース（解析・展開）した後は、数値は数値として、リストはリストとして、各言語の適切なデータ型に自動的に変換されます。

JSONが持つ基本データ型

JSON（JavaScript Object Notation）の規格自体には、文字列以外にも明確に6つのデータ型が定義されています。

JSONの型 表記例 意味
String "こんにちは" 文字列（必ずダブルクォーテーションで囲む）
Number 42, 3.14 数値（整数・小数の区別なし。クォーテーションで囲まない）
Boolean true, false 真偽値
Null null 値が存在しない（空である）こと
Object {"key": "value"} キーと値のペアの集まり
Array [1, 2, 3] 複数の値を順序付けて並べたリスト

参考: JSON公式サイト (json.org)

Python・Go・JavaScriptでの型の扱い

各プログラミング言語でJSONを読み込む際、これらのデータ型は言語ごとの組み込み型にマッピングされます。それぞれの扱いを見ていきましょう。

1. Pythonの場合

Pythonでは標準の json モジュールに備わっている json.loads() を使ってJSON文字列をパースします。型はPythonのデータ構造へ自然に変換されます。

JSONの型 Pythonでの型 備考
Object dict 辞書型として展開される
Array list リスト型になる
String str 文字列
Number int / float 小数点がない場合は int、あれば float に自動判別される
Boolean bool True または False (頭文字が大文字)
Null NoneType None に変換される

参考: Python 公式ドキュメント jsonモジュール

2. Goの場合

Go言語では encoding/json パッケージの json.Unmarshal() を使用します。Goは静的型付け言語であるため、通常は受け皿となる構造体（struct）を事前に定義し、そこにマッピングします。

ただし、どんなデータ構造が来るか分からない場合など、型を特定せずに interface{}（任意の型を受け入れる型）で受け取った場合、デフォルトで以下のように解釈されます。

JSONの型 Goでの型 (interface{} で受けた場合) 備考
Object map[string]interface{} 文字列をキーとするマップ
Array []interface{} インターフェースの配列
String string 文字列
Number float64 要注意: 整数であってもすべて float64 として解釈される
Boolean bool true または false
Null nil nil に変換される

参考: Go 公式ドキュメント encoding/json

3. JavaScript (JS) の場合

JSONはもともとJavaScriptのオブジェクト記法から派生したデータ形式なので、親和性が最も高いです。JSON.parse() メソッドを使用すると、JSの型にそのまま変換されます。

JSONの型 JSでの型 備考
Object Object オブジェクト
Array Array 配列
String String 文字列
Number Number 全て倍精度浮動小数点数（JSの標準仕様）
Boolean Boolean true または false
Null null null

参考: MDN Web Docs JSON.parse()

通信のパケット上やファイル内では単なるテキストデータですが、コード上で適切にパースさえすれば、ご自身で改めて数値や配列にキャスト（型変換）し直す必要はありません。

逆に、JSONに変換してリクエストボディにくっつける場合については？

フロントエンド言語としてJS、Dart（Flutter）の二つについて教えて

AI:

プログラム内のデータをリクエストボディに乗せる場合、HTTP通信は基本的に「テキストデータ」のやり取りとなるため、プログラム内のデータ構造（オブジェクトやマップなど）を「1つの長い文字列（JSON文字列）」に変換（シリアライズ・エンコード）する必要があります。

この変換処理を行うと、送信されるデータは型情報を保った「JSON規格のテキスト」になり、それを受け取ったサーバー側が再びパースすることで元の型として解釈できるようになります。

JavaScript（フロントエンド）とDart（Flutter）での変換方法と、それぞれの型の扱いについて解説します。

1. JavaScript の場合

JavaScriptでは、標準組み込みオブジェクトの JSON.stringify() を使用してオブジェクトをJSON文字列に変換します。

実装例（Fetch APIを使用）

JavaScript 
const requestData = {
  name: "Taro",
  age: 25,
  isStudent: true,
  skills: ["Flutter", "JS"]
};

// JSON.stringify() でオブジェクトからJSON文字列に変換
const jsonString = JSON.stringify(requestData);

fetch('https://api.example.com/data', {
  method: 'POST',
  headers: {
    // サーバーに「これはJSON形式のテキストです」と伝えるための重要なヘッダー
    'Content-Type': 'application/json' 
  },
  body: jsonString // 文字列化されたデータを入れる
});

JSの型 → JSONへの変換ルールと注意点

基本的にはそのまま変換されますが、JavaScript特有の型についてはいくつか注意すべき挙動があります。

JSの型 JSONの型 備考・注意点
String String そのまま変換される
Number Number NaN や Infinity は例外的に null に変換される
Boolean Boolean そのまま変換される
Object, Array Object, Array そのまま変換される
null Null そのまま変換される
Date オブジェクト String ISO 8601形式の文字列（例: "2026-08-25T09:38:46.000Z"）に自動変換される
undefined / 関数 / Symbol （省略される） オブジェクトの値として含まれていた場合は**キーごと無視（削除）**される。配列の中にあった場合は null に置換される

参照元: MDN Web Docs - JSON.stringify()

2. Dart (Flutter) の場合

Dartでは、標準ライブラリの dart:convert パッケージに含まれる jsonEncode() を使用して、MapやListをJSON文字列に変換します。

実装例（http パッケージを使用）

Dart 
import 'dart:convert'; // jsonEncode を使うために必要
import 'package:http/http.dart' as http;

Future<void> sendData() async {
  final Map<String, dynamic> requestData = {
    'name': 'Taro',
    'age': 25,
    'isStudent': true,
    'skills': ['Flutter', 'Dart']
  };

  // jsonEncode() でMapからJSON文字列に変換
  final String jsonString = jsonEncode(requestData);

  await http.post(
    Uri.parse('https://api.example.com/data'),
    headers: {
      'Content-Type': 'application/json', // 必須ヘッダー
    },
    body: jsonString,
  );
}

Dartの型 → JSONへの変換ルールと注意点

Dartは静的型付け言語であるため、変換対象としてサポートされていない型を jsonEncode に渡すとエラー（例外）が発生します。

Dartの型 JSONの型 備考・注意点
String String そのまま変換される
int, double Number double.nan や double.infinity はそのままではエラーになる
bool Boolean そのまま変換される
Map<String, dynamic> Object キーは必ず String である必要がある
List Array そのまま変換される
Null Null そのまま変換される
DateTime （エラー） そのままでは JsonUnsupportedObjectError が発生するため、事前に .toIso8601String() を呼び出して String に変換しておく必要がある
カスタムクラス （要設定） 独自定義したクラスをそのまま渡すとエラーになる。クラス内に Map<String, dynamic> toJson() メソッドを定義しておけば、jsonEncode が自動的にそれを呼び出して変換してくれる

参照元: Dart API Reference - dart:convert jsonEncode

まとめ

どちらの言語においても、リクエストボディにデータをくっつける際は以下の2点が鉄則となります。

  1. 関数（JSON.stringify / jsonEncode）を使ってプログラム内のデータを「JSON形式の文字列」に変換してから body に渡す。

  2. HTTPリクエストのヘッダーに Content-Type: application/json を必ず指定する。（これを忘れると、文字列は送られていてもサーバー側が「ただのプレーンテキスト」と勘違いし、パースに失敗することが多々あります）

AI:

はい、その認識で完璧です！素晴らしいまとめだと思います。

要点を整理いただいた通り、JSONを通じたデータのやり取りは以下のイメージを持っておけば実務でもスムーズに対応できます。

1. 受信側の基本スタンス

  • JSON自体に型情報が含まれているため、言語標準のパーサー（JSON.parse() や json.loads() など）を通すだけで、自然と言語ごとの扱いやすい型（辞書、リスト、数値など）に変換されます。

  • 開発者は「文字列からどうやって数値に戻すか」といった変換処理を意識する必要はなく、変換後のデータ構造をそのまま活用できます。

2. 送信側の基本スタンス

  • データを送信する際は、使用している言語の「JSONエンコードの仕様（クセ）」を把握しておくことが重要です。

  • 特にDart（Flutter）のような静的型付け言語では、DateTime 型や独自クラスをそのまま変換しようとしてエラーになるのが「あるある」です。

  • また、JavaScriptでは undefined が消えてしまうなど、言語特有の挙動を知っておかないと「送ったはずのデータがサーバーに届いていない」というバグを生む原因になります。

＋αの現場の知恵 最後に一つだけ付け加えるとすれば、送信側で忘れてはならないのが Content-Type: application/json ヘッダーの付与 です。どれだけ綺麗にJSON文字列へ変換して送信しても、このヘッダーがないと受信側のサーバーが「ただの文字の羅列が送られてきた」と判断してしまい、パースしてくれないことがあります。
